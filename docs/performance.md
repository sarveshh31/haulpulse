# HaulPulse performance notes

All numbers measured on a laptop (Windows 11, 16 GB RAM, Docker, default PostgreSQL 15 config)
using synthetic data. Source files are generated by a seeded simulator, so the data is synthetic by design.

## Pipeline throughput (1,064,228 trips across 209 daily files)

| Stage | Seconds | Rows/sec |
|---|---:|---:|
| Bronze load (COPY, 209 files) | 34.6 | ~30,800 |
| Silver validation + upsert (209 files) | 130.9 | ~8,100 |
| dbt run (incremental fact + dims + marts) | 29.4 | ~34,000 |
| dbt test | 12.1 | - |
| **Total (ingest to tested)** | **207.0** | **~5,100** |

Silver is the bottleneck (63% of runtime): per-file Python validation and per-file upserts.
Next optimization would be batching files per transaction.

## Reconciliation at scale
12 of 12 injected defect types matched exactly: 52,041 rows quarantined (4.9%, including exact duplicates)
plus 21,318 values auto-corrected (city spellings, status casing), about 73K injected defects in total.

## Query performance (1,016,628 rows, `EXPLAIN ANALYZE`, median of 7 runs)

| Query | No index | + B-tree indexes | Monthly partitions only |
|---|---:|---:|---:|
| City revenue, 1 week | 54.57 ms | **3.56 ms (15x)** | 13.86 ms (3.9x) |
| All cities, 1 month | 65.89 ms | 48.61 ms (1.4x) | 36.44 ms (1.8x) |
| Single trip lookup | 63.68 ms | **0.02 ms** | 71.10 ms (0.9x) |

Full table, plans and block counts: [benchmarks.md](benchmarks.md).

### Findings
1. **Indexes are the main win.** A composite index on (city_key, requested_at) cut the selective
   query from 54.6 ms to 3.6 ms, and the trip_id index turned a full scan into a 0.02 ms lookup.
2. **Partition pruning reduces I/O.** A one-month query reads 5,504 blocks instead of 37,578
   (85% fewer) with no index at all.
3. **Partitioning has a cost.** Lookups by a non-partition key probe every partition
   (0.09 ms vs 0.02 ms), and a unique index must include the partition key.
4. **Indexes cost storage:** 293 MB to 420 MB (+43%) for three indexes.
5. **Combining both did not beat indexes alone at this size.** The planner chose a plain index
   scan for the selective query after partitioning, which was no faster than a sequential scan of
   one partition.

### Decision
The production `fact_trips` table is indexed (configured in dbt). Partitioning is documented as
the recommendation for roughly 10x this volume or for dropping old months cheaply.
